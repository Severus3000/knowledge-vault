# Python 并发（Concurrency）总览

Python 有三种并发方式，解决同一个问题：**blocking（阻塞）**。

---

## 什么是 Blocking

程序从上往下一行一行执行。如果某一行要等很久（网络请求、跑测试），整个程序卡住，什么都干不了。

```python
result = requests.post("some-api")   # 卡在这里等 3 秒
print("继续")                         # 必须等上面完成才能执行
```

---

## 三种解决方式

| | 线程 Thread | 进程 Process | 异步 Async |
|--|------------|-------------|-----------|
| 执行者数量 | 多个线程 | 多个进程 | 一个线程 |
| 内存 | 共享 | 各自独立 | 共享 |
| 通信方式 | 直接读写变量 | IPC（stdout等） | 直接读写变量 |
| 适合场景 | 后台跑命令 | 隔离子任务 | 大量网络请求 |
| 风险 | race condition | IPC 复杂 | 所有代码都要 async |
| 开销 | 轻量 | 重（新进程） | 最轻 |

### 一句话区分

```
线程：同一个房间里两个人干活，共用一张桌子（快但容易抢东西）
进程：两个人在各自的房间干活，结果通过门缝递纸条（安全但传递麻烦）
异步：一个人在等快递的时候先去拆另一个快递（高效但只有一个人）
```

### Agent 场景对应

| 并发方式 | Agent 场景 |
|---------|-----------|
| 线程 | 主 agent 开后台线程跑 pytest，自己继续处理用户消息 |
| 进程 | 主 agent 启动多个 parallel agent（独立进程）同时探索代码库 |
| 异步 | agent 同时发出多个 API 请求（查数据库 + 搜知识库），等待时间重叠 |
